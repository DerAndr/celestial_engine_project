## 1. Vision & Core Experience

When the user holds the **QUERY** button (or triggers via Companion App) and speaks an incantation or request:
> *"Celestial Sphere, cast a veil of cosmic starlight to protect our expedition!"*  
> *"Awaken the infernal solar flare — incinerate this bug!"*  
> *"Channel the ancient chronomancy runes — divine the flow of time!"*

The staff should not merely give a dry text answer:
1. **Witty / Mystical Persona Response**: Generated by LLM with an ancient-futuristic techno-arcane personality ("Don't Panic", sarcastic oracle, or celestial archmage).
2. **Dynamic Procedural Light Show (43 LEDs)**: The LLM generates a **unique color scheme, animation style, and rhythmic cadence** customized to the specific spell.
3. **Synchronized Speech & Sonic Feedback**: Pre-speech arcane surge SFX -> Voice response modulated with real-time VU halo -> Settling into an ambient enchanted afterglow.

## 2. LLM Spell Generation Architecture

### 2.1 Prompt Engineering & Output Protocol
The LLM prompt is augmented with a structured schema for spell parameters. Instead of bulky JSON that delays streaming, we use a hybrid markdown or structured metadata tag that streams cleanly:

#### Format A: Lightweight Arcane Tag (Streaming-Friendly)
```text
[SPELL: SolarFlare | #FF1100 | #FFAA00 | #FFFF55 | ANIM:SURGE | SPEED:140 | SFX:WARP]
The fiery wrath of Kepler-452b surges through the concentric runes! Behold the solar storm!
```

#### Format B: JSON Output (Structured Function Calling)
```json
{
  "speech": "The cosmic currents obey. Astral protection is woven around you.",
  "spell": {
    "name": "Astral Aegis",
    "school": "COSMIC_ABJURATION",
    "palette": {
      "core": "#00FFDD",
      "mid": "#7B00FF",
      "outer": "#0022FF"
    },
    "animation": "VORTEX_EXPAND",
    "speed_ms": 80,
    "vu_reactive": true,
    "sfx_intro": "CHIME_ASCENDING",
    "afterglow": "STARRY_SPARKLE"
  }
}
```

### 2.2 Processing on Android Phone (Mobile Brain Host)
1. **Extraction**: `GemmaModelEngine` streams the response. The regex parser instantly captures `[SPELL: ...]` or JSON header before the text.
2. **Binary Command Dispatch**: Phone immediately sends a new network packet `NET_MSG_SPELL_CAST` (or `NET_MSG_APP_COMMAND` with subcommand `CMD_SET_SPELL`) to Pico over UDP.
3. **Audio Synthesis & Streaming**: Phone synthesizes speech via `StaffTtsSynthesizer` and streams PCM chunks back to Pico.

## 4. Procedural Animation Primitives on Pico 2 W (`leds.c`)

Rather than streaming 43 RGB bytes 60 times a second over Wi-Fi (which causes packet drops and jitter), Pico runs a high-performance 2D polar-coordinate kinematics engine. The 43 LEDs are mapped to continuous polar coordinates $(r, \theta)$:
- Core (Ring 0): $r = 0..1$, 7 LEDs (Center + 6 at 60° increments).
- Mantle (Ring 1): $r = 2$, 12 LEDs at 30° increments.
- Barrier (Ring 2): $r = 3.2$, 24 LEDs at 15° increments.

This enables advanced topological animations that transcend simple single-ring loops:

### 4.2 Kinematic Parameters Sent by LLM
LLM can customize each engine with fine-grained motion modifiers:
- `direction`: `OUTWARD`, `INWARD`, `CW` (clockwise), `CCW` (counter-clockwise), `ALTERNATING`
- `snake_length`: 3 to 18 LEDs
- `wave_frequency`: 0.5 Hz to 5.0 Hz
- `vu_coupling`: 0.0 (ambient) to 1.0 (strict voice amplitude lock)
- `palette`: Core, Mid, Outer, and Accent/Sparks colors

## 6. Stop / Interrupt Mechanics for Spells

Spells can be dramatic and intense. If a user casts a spell by accident or the staff speaks too long:
- **Physical Cancel**: A single click on the Rotary Encoder button (PEC11R SW) or QUERY tap immediately triggers `net_client_cancel()`.
- **Light & Sound Cut**: Audio stops instantly, LEDs collapse inward in a 200 ms dissipating sparkle ("fizzling spell"), and state returns to `IDLE`.
- **App Cancel**: Large prominent `[STOP / DISSIPATE]` button on Android HUD.
