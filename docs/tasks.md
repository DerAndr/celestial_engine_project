# Задачи — сначала автономный Pico, затем Raspberry Pi

Зафиксировано: **2026-10-11**. Это список дальнейшей работы, а не выполненные изменения. Сегодня — только документация, коммит и push; продолжение в следующей сессии.

## Что уже работает

- Pico 2 W, OLED, энкодер, QUERY, микрофонный индикатор, локальные звуки и музыка работают; интеграция ещё частичная.
- Пользователь исправил плохую пайку аудио: звук и регулировка громкости восстановились. GAIN усилителя остаётся неподключённым.
- **Пользователь починил кольцо на 16 позиций перемычкой, обойдя один битый светодиод.** Светодиод не выпаян; перемычка идёт от общего DIN кольца к верхнему правому контакту повреждённого LED, определённому прозвонкой как DOUT. Остальные позиции кольца светятся; повреждённая остаётся тёмной.
- Физическая цепочка: **7 → 12 → 24 → починенное 16-позиционное кольцо**. Последнее кольцо подключено после большого, его DO свободен, питание съёмное от прежней шины +5 V и общей земли.
- 1.0.7 дала подтверждённую пользователем работу всех четырёх колец на 4% яркости. COSMIC SNAKE также подтверждён как хороший. Белые всполохи отдельных пикселей в RAINBOW ещё не устранены; точное адресное отображение починенного кольца и изоляция старого неисправного выхода не подтверждены.
- Основная сборка снова называется `celestial_firmware.uf2`. Текущая подготовленная версия — **1.0.10-FOUR-RINGS**; отдельная диагностика — `celestial_ring_experiment.uf2`, **1.0.10-RING-DIAGNOSTIC**. Обе собраны и проверены программно, новый физический результат пока не получен.

## Приоритеты на Pico

Выполнять сверху вниз, по одному наблюдаемому результату. Не переходить к новым аппаратным этапам, пока текущая проблема не разобрана.

1. **[ВЫПОЛНЕНО] Проверка четвёртого кольца и белых всполохов.** Пользователь подтвердил физическое наблюдение: паразитные белые всполохи на 4-м кольце больше не наблюдаются, тёмные фоны в PULSAR/VOICE/VORTEX работают корректно. Ограничение яркости 4% и временная перемычка зафиксированы.
2. **[ВЫПОЛНЕНО] Локальный аудиотракт и захват речи QUERY на Pico.** Удержание QUERY записывает 16 кГц 16-бит моно в буфер RAM (до 5 секунд, 160 КБ), а отпускание завершает запись и запускает воспроизведение. Добавлен программный предусилитель +14 дБ (`pcm16_gain = 5.0f`) и стартовая громкость 35%. Физически подтверждено пользователем ("теперь лучше!"). См. [эксперимент 026](experiments/026-mic-record-ram-buffer.md).
3. **[ОТЛОЖЕНО НА ПОТОМ — УКРАШАТЕЛЬСТВА] Полноценно переписать светомузыку и эффекты на четыре кольца.** Перенесено в бэклог по решению пользователя для скорейшего выхода на интеграцию с Raspberry Pi 5.
4. **[ТЕКУЩИЙ ПРИОРИТЕТ — P9] Связь Pico ↔ Сервер «мозга» по Wi-Fi.** Зафиксировать минимальный бинарный/UDP протокол стриминга: удержание QUERY стримит 16 кГц PCM пакеты на сервер (сначала mock-сервер на ПК, затем Pi 5), сервер сохраняет `query.wav` и шлёт обратно ответный PCM звук, Pico воспроизводит через I2S DMA.
5. **[P10] Перенос сервера на Raspberry Pi 5.** Запуск автономного Hotspot на Pi 5, развёртывание Sherpa-ONNX (STT) → локальная LLM → Piper (TTS). Посох автоматически коннектится к Pi 5 в походном режиме.

## Готовность Pico перед разработкой мозговой части

- [ ] Посох самостоятельно загружается, переключает режимы, показывает статус, играет локальные звуки и управляет четырьмя кольцами без Pi и сети.
- [ ] Белые всполохи разобраны; эффекты и светомузыка на четыре кольца согласованы, а аппаратные ограничения записаны.
- [ ] QUERY имеет ограниченную запись и понятное завершение, локальное воспроизведение и отмена стабильны.
- [ ] Потеря/возврат связи не зависают устройство и не ломают автономную работу.
- [ ] Протокол описан и проверен с имитатором; есть воспроизводимая рабочая прошивка и короткий журнал физической проверки.

## Затем Raspberry Pi и объединение

7. **Разрабатывать Raspberry Pi 5 отдельно по готовому контракту.** Отдельный сервис STT → агент/LLM → TTS, выбор языка и режимов, работа с сохранёнными аудиопримерами и имитатором Pico. Не требовать подключённого посоха для каждого изменения сервиса.
8. **Объединить две независимо работающие части (P10).** QUERY hold → запись → release → передача → обработка на Pi → возврат аудио → воспроизведение → IDLE. Проверить отмену, таймаут, обрыв сети, повторное подключение и сохранение локального режима.
9. **После функционала — переносное питание и механика (P11/P12).** Проверить питание посоха отдельно от батарейной системы Raspberry Pi 5. Затем надёжность монтажа, съёмность, крепления и корпус. Не смешивать две системы питания и не расширять список покупок без доказанной необходимости.
